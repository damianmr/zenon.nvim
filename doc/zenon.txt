*zenon.txt*                  zenon.nvim buffer writing mode               *zenon*

zenon.nvim requires Neovim 0.12 or newer. Its Lua code is original and MIT licensed.
It has no required runtime dependencies.

COMMANDS                                                     *zenon-commands*

:Zenon [percentage [minimum [maximum]]]                              *:Zenon*
    Enable or resize the current buffer. Repeating this command keeps it enabled.
    Percentage refers to the host split, including its owned margins. Minimum
    and maximum are text columns. For example, :Zenon 60 80 120 requests 60%,
    with at least 80 and at most 120 text columns. If there is too little space,
    zenon.nvim uses the available width.
    Omitted arguments keep the buffer's overrides or use setup defaults.

:Zenoff                                                            *:Zenoff*
    Disable the current buffer and restore its views and mappings.

:Zenoff!
    Disable all buffers. Disabling clears runtime overrides.

CONFIGURATION                                                 *zenon-options*

Setup is optional. Defaults: >lua
    require("zenon").setup({
      width = 50,
      min_width = 80,
      max_width = nil,        -- no maximum
      showbreak = "↪",       -- false or a string
      scrolloff = 10,
      breakindent = true,
      wrap = true,
      linebreak = true,
      wrap_navigation = true,
      hide_eob = true,
      dim = 0.15,             -- false or a number from 0 to 1
      ruler = false,
      window_options = {
        number = false,
        relativenumber = false,
        signcolumn = "no",
        foldcolumn = "0",
        list = false,
        cursorline = false,
        cursorcolumn = false,
      },
      integrations = { lualine = true },
      hooks = {},
    })
<
See |'showbreak'|, |'scrolloff'|, |'breakindent'|, |'wrap'| and |'linebreak'|.

showbreak marks a wrapped continuation row. It does not add a newline to the
file. Wrapped rows keep the original line's indentation. These settings change
the display. Formatting and spell checking stay as configured;
window_options.spell=true can enable spell checking in zenon.nvim views.

ruler is global. If enabled buffers request different values, false takes
priority. After the last enabled buffer is disabled or wiped, zenon.nvim restores
the old value if it still matches what zenon.nvim set. showcmd, statuslines, and
other global UI settings stay as configured.

Omit max_width for no maximum beyond the available space. Use
require("zenon").enable({ max_width = false }) to remove a maximum inherited
from setup or an earlier enable call.

The percentage must be finite and in (0, 100]. min_width must be a positive
integer. When set, max_width must be a positive integer at least min_width;
false also means no maximum. scrolloff must be a nonnegative integer. Unknown
options are rejected. window_options accepts only window-local Neovim options.
setup replaces setup defaults; runtime buffer overrides still take priority.
zenon.nvim checks options before changing state. If setup or enable fails, zenon.nvim
restores the old session or removes the new one.

WIDTH AND SPLITS                                                   *zenon-width*

The host region is the editing window plus its margins and separators. Width
percentages use the host region after subtracting retained gutters, such as
line numbers. min_width and max_width count text columns after those gutters.
zenon.nvim calculates the target width as follows: >text
    text_space = max(1, host_columns - retained_gutters)
    desired = floor(text_space * width / 100)
    target = min(text_space, max_width or text_space,
                 max(min_width, desired))
<
An omitted or false max_width means no cap. Available space takes priority over
min_width. Neovim's window minimums and separators still apply. Small gaps use
one margin; with only one spare column, text can be one column narrower than the
target.

zenon.nvim updates layout after window and terminal size changes. A vertical split
shares the old host region, including margin space. A horizontal split keeps the
full host width. Existing sidebars keep their size. Later manual resizes also
stay in place. zenon.nvim groups related window events into one update. It leaves
margins alone when they already have the requested width.

NAVIGATION                                                   *zenon-navigation*

Normal-mode j/k move by visible rows, including with a count. 5j moves five
visible rows down and 5k moves five visible rows up. Operator-pending and Visual
mappings are preserved. Existing buffer-local mappings take precedence.

0, ^ and $ keep their file-line meanings. Use |g0|, |g^| and |g$| for screen rows.
Set wrap_navigation=false to preserve configured j/k movement.

LAYOUT AND SCOPE                                                 *zenon-layout*

Enable zenon.nvim for a buffer. It can have a view in several windows or tabs, each
with its own width and saved options. Splitting a view shares the whole pane,
including margins. Disabling keeps the resulting native splits. Changing buffers
restores the outgoing view's options; returning creates its margins again.
Focus changes keep the buffer enabled.

The file stays in its editing window. Blank scratch splits form the margins.
Other splits stay visible. zenon.nvim dims the margins and keeps transparent
backgrounds transparent. Margin colors follow the colorscheme. Directional
navigation skips margins. In enabled buffers Ctrl-W w, Ctrl-W Ctrl-W and
Ctrl-W W cycle through editing windows.
Existing buffer mappings take priority.

Margins have buftype=nofile, filetype=zenon-margin and w:zenon_padding=v:true.
Window pickers and :windo can see them. Exclude margins from those tools when
needed.

The lualine adapter excludes margins from winbars and window statuslines to hide
[No Name] [-] titles. It uses an already loaded lualine instance and keeps file
titles and the global statusline. It restores exclusions that still match what
zenon.nvim set and keeps existing entries and later user changes. Set
integrations.lualine=false to manage this yourself.

zenon.nvim restores options and mappings only if they still match what it set. It
keeps later user changes. Global mappings still apply after disable. Remove
global writing mappings if you want them only inside zenon.nvim.

Saved local option values include inherited values. Replacing the buffer in a
window restores that window's options; returning to an enabled buffer creates a
new view. Before quitting a view, zenon.nvim removes its margins. If closing the last
editing window leaves only margins, zenon.nvim reuses one for the file.

LUA AND HOOKS                                                      *zenon-api*

require("zenon").enable(opts?, bufnr?)
    Enable or resize a normal buffer. Defaults to the current buffer.
require("zenon").disable(bufnr?)
    Disable a buffer. Defaults to the current buffer.
require("zenon").disable_all()
require("zenon").is_enabled(bufnr?)
    Return a boolean. Defaults to the current buffer.
require("zenon").status(bufnr?)
    Return { enabled, bufnr, reason, session_count, windows }.
    Each window entry has winid, width, available.
require("zenon").is_margin(winid?)
    Whether a valid window is currently a margin. Defaults to the current window.

hooks.on_enable(ctx)
    Runs once per buffer session, after views are created. May return a cleanup
    function receiving context when the session ends. Errors roll back enable.
hooks.on_disable(ctx)
    Runs after session resources are removed. Errors are reported.
hooks.on_resize(ctx)
    Runs after a view is created or its geometry changes. Errors are reported.

Context: bufnr, reason, session_count, windows. The window list may be empty for
hidden buffers or after disable. Use session_count for external state shared by
buffers. Hooks can read state but must not change zenon.nvim's state inside a callback.

Twilight is a separate plugin that dims inactive text regions. It is not loaded
by zenon.nvim. Configure external integrations through hooks.

INTEGRATIONS                                               *zenon-integrations*

require("zenon").register_integration(name, spec)
    Register an adapter. Names must be unique nonempty strings. Returns an
    idempotent unregister() function that detaches and removes the adapter.
    Enable it with setup({ integrations = { [name] = true } }). Registration
    and configuration can occur in either order. Late registrations apply to
    enabled buffers on the next scheduled update.

An integration has these callbacks:

available() -> boolean
    Optional. Check whether the other plugin is already available, for example
    through package.loaded. Omit this callback for an always-available adapter.
    zenon.nvim checks availability on enable and scheduled window events.
    zenon.nvim does not load the other plugin or poll for it.
attach(ctx) -> state
    Required. Called once when at least one enabled buffer requests the adapter
    and it is available. Runs before new margins are created, so ctx.windows
    and ctx.margins may be empty. Prepare the integration and return any state
    needed by update and detach. If attach raises an error after changing
    external state, it must roll back those partial changes itself.
update(ctx, state)
    Optional. Called after layout updates. Receives current windows and
    margins, including new and resized views, with the state returned by attach.
detach(ctx, state)
    Optional. Restore owned state when no enabled buffer requests the adapter,
    it becomes unavailable, or unregister() is called. Margins may already be
    gone. Keep later user changes to the other plugin.

Each callback gets a separate context snapshot:
    buffers: enabled buffer IDs, including hidden buffers.
    windows: { winid, bufnr, width, available } for visible editing views.
    margins: { winid, bufnr, owner, side } for margin windows. owner is the
             editing window ID; side is "left" or "right".
Lists cover all tabs and are sorted by buffer or window ID. Buffers share the
adapter; any enabled buffer requesting it keeps it active. Use hooks for behavior
that should run separately for each buffer.

Callbacks can read state but must not change zenon.nvim's state inside a callback.
zenon.nvim reports errors and continues editor cleanup and other integrations.
An update error detaches that adapter. After an availability, attach, or update
error, the adapter is not retried until it is disabled and enabled again. A
detach error is reported once and does not block cleanup of other resources.

The built-in lualine adapter lives in lua/zenon/integrations/lualine.lua and uses
this same API. The layout and session code contain no lualine-specific behavior.
It temporarily adds zenon-margin to lualine's disabled_filetypes.statusline and
disabled_filetypes.winbar through its public get_config and setup functions.

MARGIN CONTRACT                                                *zenon-margins*

The following identifiers are available to external integrations:
    require("zenon").is_margin(winid?)
    w:zenon_padding=v:true on margin windows
    filetype=zenon-margin on margin scratch buffers
    buftype=nofile, buflisted=false, modifiable=false, swapfile=false

Margins are split windows, visible to :windo, window pickers and window
counts. Use the identifiers above to filter them. Two margins of one editing
view may share a scratch buffer; buffer IDs do not identify individual windows.

Window and buffer IDs can change during resize, buffer replacement, or layout
repair. Use IDs from the current context and check that they are valid before
later work. Do not edit margin buffers or move, close, or reuse their windows.
zenon.nvim sets their filetype before creating windows and suppresses native window
creation autocommands. Use update(ctx, state) for window changes. Internal tables
and highlight group names are private.
